Why Rivet

Racket is great at logic. Commercial apps need native UI.

There was no direct path from a Racket backend to the modern first-party desktop stacks. Rivet fills that gap.

First-party native UI

WinUI 3 on Windows, SwiftUI/AppKit on macOS, and GTK4 on Linux — each platform stays itself.

One backend contract

Typed RPC, events, shared state, cancellation and lifecycle over the same RVT1 protocol, projected into the shared Keel contract.

Generated native clients

raco rivet build generates typed Swift, C++, and Kotlin APIs from your declarations.

Embedded Racket CS

The Racket runtime lives inside the application process — no external backend to manage.

Exact runtime matching

Rivet requires Racket 9.0+ (CS), stages the installed runtime exactly, and never silently falls back to a nearby version.

Safe threading by design

The native side only sees framed RVT1 messages and generated values.

Real-time charts

Rolling-time-series native chart widgets on every desktop host, over one typed data plane.

Updates built in

Signed release feeds on every desktop — bundle swap on macOS, MSI handoff on Windows, AppImage replacement on Linux.

Linkable packages

Hosts link released packages — SwiftPM on macOS, static libraries on Windows and Linux — never compiled sources.

Positioning

Two projects, two trade-offs.

The Racket desktop stack: Rivet and Glaze — different trade-offs, not replacements for one another.

Rivet Glaze
UI stack WinUI 3 / SwiftUI / GTK4 HTML/CSS/JS + WebView
Native widgets first-party OS UI no

Best fit platform-native commercial apps web-tech desktop apps

Build one verifiable result.

先完成一个可验证的结果。

Choose Rivet when first-party native interaction is worth maintaining separate SwiftUI, WinUI 3 and GTK4 UIs. Racket owns shared domain logic; native hosts own rendering and OS interaction. For a shared HTML/CSS interface, evaluate Glaze instead.

当第一方原生交互值得维护 SwiftUI、WinUI 3、GTK4 三份界面时，选择 Rivet。共享领域逻辑归 Racket，渲染与系统交互归原生宿主。需要共享 HTML/CSS 界面时可评估 Glaze。

Racket CS 9.0+ and the target platform’s native toolchain. Desktop delivery has explicit capability/acceptance classes; mobile runtime or companion foundations are not a generated, signed and packaged app workflow.

需要 Racket CS 9.0+ 和目标平台原生工具链。桌面交付有明确能力与验收分级；移动运行时或伴随端基础不等于已生成、签名和打包的应用工作流。

Run inspect and doctor in the generated project, complete one backend mutation and observe its persisted result in the packaged native app. Keep one product interaction contract across hosts and adapt shortcuts, focus and window behavior to each OS. A unit test or screenshot alone does not establish product parity.

在生成项目内运行 inspect 和 doctor，完成一个后端修改，并在打包原生应用中观察持久化结果。跨宿主保持一个产品交互契约，快捷键、焦点和窗口行为遵循各系统习惯。单元测试或截图本身不能证明产品一致性。
